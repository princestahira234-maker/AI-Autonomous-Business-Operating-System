# Machine Learning Modules

## 1. Revenue AI — Revenue Forecasting

### Objective

Forecast future sales/revenue using historical sales patterns, store information, product families, calendar effects, holidays, oil prices, and historical sales behavior.

### Dataset

The revenue forecasting pipeline uses multiple related datasets:

- `train.csv`
- `test.csv`
- `stores.csv`
- `oil.csv`
- `holidays_events.csv`
- `transactions.csv`

### Data Processing

The pipeline includes:

- Missing-value analysis
- Duplicate detection
- Data-type validation
- Date conversion and temporal validation
- Store metadata integration
- Holiday feature engineering
- Oil-price integration
- Product-family consistency checks
- Historical lag features

### Feature Engineering

Calendar features include:

- Year
- Month
- Day
- Week of year
- Quarter
- Day of week
- Weekend indicator
- Month start/end indicators

Historical sales features include:

- 1-day lag
- 7-day lag
- 14-day lag
- 28-day lag

Transactions were evaluated during feature development but excluded from the final forecasting features where future-period availability could introduce leakage.

### Model

**XGBoost Regressor**

Main configuration:

- Objective: `reg:squarederror`
- Estimators: 600
- Learning rate: 0.05
- Maximum depth: 8
- Minimum child weight: 5
- Subsample: 0.80
- Column sampling: 0.80
- Tree method: `hist`
- Random state: 42

### Evaluation

The model was evaluated using:

- RMSE
- MAE

A chronological validation strategy was used instead of a random split.

### Model Artifacts

- `xgboost_final_model.json`
- `xgboost_onehot_encoder.pkl`

# 2. Inventory AI — Demand Forecasting

### Objective

Predict future product demand at store/product level to support inventory planning and reduce the risk of stock shortages or excessive inventory.

### Dataset

`sal​es_data.csv`

Target variable:

`Demand`

### Data Processing

The inventory pipeline includes:

- Dataset quality auditing
- Missing-value analysis
- Duplicate checks
- Infinite-value checks
- Date validation
- Store/product coverage analysis
- Chronological sorting
- Leakage analysis

### Historical Demand Features

Demand history was generated by Store ID and Product ID using:

- 1-day lag
- 7-day lag
- 14-day lag
- 28-day lag
- 7-day rolling mean
- 14-day rolling mean
- 28-day rolling mean

Rolling features use shifted historical values so that the current target is not included in its own historical calculation.

`Units Sold` and `Units Ordered` were excluded from the final feature set because their availability can depend on information that would not necessarily be known when forecasting future demand.

### Data Split

A chronological split was used:

- Training: through `2023-06-24`
- Validation: `2023-06-25` to `2023-10-12`
- Test: after `2023-10-12`

### Model

**XGBoost Regressor**

Final configuration:

- Estimators: 2000
- Learning rate: 0.03
- Maximum depth: 8
- Minimum child weight: 3
- Subsample: 0.80
- Column sampling: 0.80
- Objective: `reg:squarederror`
- Tree method: `hist`
- Early stopping: 100 rounds
- Random state: 42

Negative demand predictions are clipped to zero before final use.

### Evaluation

The inventory model was evaluated using:

- RMSE
- MAE

### Model Artifacts

- `inventory_xgboost_model.pkl`
- `inventory_onehot_encoder.pkl`
- `inventory_test_predictions.csv`

### Inventory Model Download

# 3. Customer AI — Customer Churn Prediction

### Objective

Predict customers who are at higher risk of churn based on customer profile, subscription information, service usage, billing behavior, and customer tenure.

### Dataset

`Telco-Customer-Churn.csv`

Target:

`Churn`

- `No` → 0
- `Yes` → 1

### Data Processing

The pipeline includes:

- Removal of `customerID`
- Numeric conversion of `TotalCharges`
- Missing-value treatment
- Binary target encoding
- Training/validation/test separation
- Feature preprocessing fitted only on training data

### Feature Engineering

Additional business features include:

- `TenureYears`
- `IsNewCustomer`
- `IsLongTermCustomer`
- `MonthlyChargesLog`
- `TotalChargesLog`
- `AvgMonthlyValue`
- `ServiceCount`
- `HighMonthlyCharge`
- `MonthToMonth`
- `ElectronicPayment`

### Models Evaluated

Three classification approaches were evaluated:

1. Logistic Regression
2. Random Forest
3. XGBoost Classifier

The final selected model was:

**Logistic Regression**

Class weighting was used to address class imbalance.

### Threshold Optimization

The classification threshold was tuned on validation probabilities.

Final operational threshold:

**0.60**

### Final Test Performance

| Metric | Score |
|---|---:|
| Accuracy | 0.7786 |
| Precision | 0.5657 |
| Recall | 0.7139 |
| F1 Score | 0.6312 |
| ROC-AUC | 0.8498 |
| PR-AUC | 0.6687 |
| Log Loss | 0.4821 |

### Model Artifacts

- `customer_churn_logistic_regression.joblib`
- `customer_churn_preprocessor.joblib`
- `customer_churn_threshold.joblib`

# 4. Transaction Risk — Anomaly / Fraud Detection

### Objective

Identify potentially fraudulent or anomalous credit-card transactions using transaction characteristics and engineered temporal/amount features.

### Dataset

`creditcard.csv`

Target:

`Class`

- `0` → Normal
- `1` → Fraud / Anomaly

### Data Processing

The pipeline includes:

- Dataset quality audit
- Duplicate analysis
- Missing/infinite-value checks
- Class imbalance analysis
- Fraud vs. normal statistical analysis
- Correlation analysis
- Transaction amount analysis
- Temporal analysis

### Feature Engineering

The final feature set contains 36 features, including:

- Original numerical transaction features
- `time_hour`
- `time_day`
- `time_hour_sin`
- `time_hour_cos`
- `amount_log`
- `amount_zscore`

### Data Split

A chronological split was used:

- Training: first 70% of the temporal range
- Validation: next 15%
- Test: final 15%

This preserves the temporal nature of transaction data.

### Model

**XGBoost Classifier**

Configuration:

- Estimators: 1000
- Maximum depth: 6
- Learning rate: 0.05
- Subsample: 0.80
- Column sampling: 0.80
- Minimum child weight: 3
- Objective: `binary:logistic`
- Evaluation metric: `aucpr`
- Tree method: `hist`
- Early stopping: 80 rounds
- Random state: 42

Class imbalance was handled using `scale_pos_weight`, calculated from the training set.

### Threshold Optimization

The decision threshold was tuned using validation data.

Final operational threshold:

**0.74**

### Final Test Performance

| Metric | Score |
|---|---:|
| Accuracy | 0.9995 |
| Precision | 0.8444 |
| Recall | 0.7308 |
| F1 Score | 0.7835 |
| ROC-AUC | 0.9781 |
| PR-AUC | 0.7756 |
| Log Loss | 0.002952 |

The final test alert rate was approximately:

**0.1053%**

### Model Artifacts

- `anomaly_xgboost_model.json`
- `anomaly_model_config.json`
- `anomaly_feature_config.json`
- `anomaly_xgboost_config.json`

# 5. Supplier AI — Late Delivery Risk

### Objective

Predict whether a supply-chain order is at risk of late delivery.

### Dataset

Primary dataset:

`DataCoSupplyChainDataset.csv`

Supporting dataset:

`DescriptionDataCoSupplyChain.csv`

Target:

`Late_delivery_risk`

- `0` → No late-delivery risk
- `1` → Late-delivery risk

### Data Processing

The pipeline includes:

- Missing-value analysis
- Duplicate checks
- Target distribution analysis
- Date validation
- Temporal ordering
- Leakage analysis
- Removal of sensitive information
- Removal of unsuitable high-cardinality identifiers

### Feature Engineering

Date features include:

- Order year
- Order month
- Order day
- Day of week
- Week of year
- Quarter
- Weekend indicator

The final feature set contains categorical and numerical business features, including:

- Shipping mode
- Customer segment
- Market
- Department
- Category
- Product
- Country/region
- Scheduled shipping time
- Order item discount
- Discount rate
- Product price
- Order item quantity
- Temporal order features

Direct post-outcome fields were removed to reduce leakage risk.

### Models Evaluated

Two major approaches were evaluated:

1. XGBoost Classifier
2. CatBoost Classifier

The final selected model was:

**CatBoost Classifier**

CatBoost was selected because of the large number of categorical business features and its native categorical-feature handling.

### Final Model Configuration

- Iterations: 2000
- Learning rate: 0.03
- Depth: 8
- L2 regularization: 5
- Random strength: 1
- Bootstrap: Bernoulli
- Subsample: 0.80
- Early stopping: 150 rounds
- Random seed: 42

### Threshold Optimization

The classification threshold was tuned using validation data.

Final operational threshold:

**0.38**

The lower operational threshold prioritizes identifying a high proportion of potentially late deliveries.

### Validation Performance

| Metric | Score |
|---|---:|
| Accuracy | 0.5956 |
| Precision | 0.5833 |
| Recall | 0.8848 |
| F1 Score | 0.7031 |
| ROC-AUC | 0.7361 |
| Log Loss | 0.563179 |

### Final Test Performance

| Metric | Score |
|---|---:|
| Accuracy | 0.5979 |
| Precision | 0.5872 |
| Recall | 0.9195 |
| F1 Score | 0.7167 |
| ROC-AUC | 0.7455 |
| Log Loss | 0.559627 |

The final test recall of **91.95%** indicates that the model identifies most of the late-delivery cases, with a deliberate trade-off toward more proactive risk alerts.

### Model Artifacts

- `supplier_catboost_model.cbm`
- `supplier_model_config.json`
- `supplier_feature_config.json`

# Machine Learning Methodology

The project follows a structured machine-learning development process:

1. **Data auditing**
   - Missing values
   - Duplicates
   - Data types
   - Invalid values
   - Target distribution

2. **Data preprocessing**
   - Cleaning
   - Encoding
   - Scaling where required
   - Missing-value treatment

3. **Feature engineering**
   - Temporal features
   - Historical lag features
   - Rolling statistics
   - Business-specific behavioral features

4. **Leakage analysis**
   - Future information checks
   - Post-outcome feature removal
   - Temporal validation

5. **Model experimentation**
   - Multiple algorithms evaluated where appropriate
   - Baseline and improved configurations

6. **Validation**
   - Chronological validation for forecasting/time-dependent problems
   - Stratified validation where appropriate for classification

7. **Threshold optimization**
   - Classification thresholds tuned according to business objectives

8. **Final model evaluation**
   - Test-set performance
   - Prediction sanity checks
   - Probability checks
   - Error analysis

9. **Model artifact creation**
   - Trained model
   - Preprocessor/encoder
   - Configuration
   - Threshold information
   - Prediction outputs where applicable
